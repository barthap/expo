`expo-file-system` provides access to files and directories stored on a device or bundled as assets into the native project. It also allows downloading files from the network.

## Configuration in app config

You can configure `expo-file-system` using its built-in [config plugin](/config-plugins/introduction/) if you use config plugins in your project ([Continuous Native Generation (CNG)](/workflow/continuous-native-generation/)). The plugin allows you to configure various properties that cannot be set at runtime and require building a new app binary to take effect. If your app does **not** use CNG, then you'll need to manually configure the library.

<ConfigPluginExample>

```json app.json
{
  "expo": {
    "plugins": [
      [
        "expo-file-system",
        {
          "supportsOpeningDocumentsInPlace": true,
          "enableFileSharing": true
        }
      ]
    ]
  }
}
```

</ConfigPluginExample>

## Usage

```js
import { File, Directory, Paths } from 'expo-file-system';
```

The `File` and `Directory` instances hold a reference to a file, content, or asset URI.

The file or directory does not need to exist — an error will be thrown from the constructor only if the wrong class is used to represent an existing path (so if you try to create a `File` instance passing a path to an already existing directory).

## Features

- Both synchronous and asynchronous, read and write access to file contents
- Creation, modification and deletion
- Available properties, such as `type`, `size`, `creationDate`, and more
- Ability to read and write files as streams or using the `FileHandle` class
- Easy file download/upload using `downloadFileAsync` or `expo/fetch`
- File previews using platform-native flows

## Examples

<Collapsible summary="Writing and reading text files">

```ts example.ts
import { File, Paths } from 'expo-file-system';

try {
  const file = new File(Paths.cache, 'example.txt');
  file.create(); // can throw an error if the file already exists or no permission to create it
  await file.write('Hello, world!'); // or `file.writeSync('Hello, world!');` for synchronous call
  console.log(file.textSync()); // Hello, world!
} catch (error) {
  console.error(error);
}
```

</Collapsible>

<Collapsible summary="Picking files using system pickers">

Usage with `expo-document-picker`:

```ts example.ts
import { File } from 'expo-file-system';
import * as DocumentPicker from 'expo-document-picker';

try {
  const result = await DocumentPicker.getDocumentAsync({ copyToCacheDirectory: true });
  if (!result.canceled) {
    const { uri } = result.assets[0];
    const file = new File(uri);
    console.log(file.textSync());
  }
} catch (error) {
  console.error(error);
}
```

Using the built-in `pickFileAsync` or `pickDirectoryAsync` method on Android:

```ts example.ts
import { File } from 'expo-file-system';

try {
  const file = new File.pickFileAsync();
  console.log(file.textSync());
} catch (error) {
  console.error(error);
}
```

</Collapsible>

<Collapsible summary="Downloading files">

Using `downloadFileAsync`:

```ts example.ts
import { Directory, File, Paths } from 'expo-file-system';

const url = 'https://pdfobject.com/pdf/sample.pdf';
const destination = new Directory(Paths.cache, 'pdfs');
try {
  destination.create();
  const output = await File.downloadFileAsync(url, destination);
  console.log(output.exists); // true
  console.log(output.uri); // path to the downloaded file, e.g., '${cacheDirectory}/pdfs/sample.pdf'
} catch (error) {
  console.error(error);
}
```

Or using `expo/fetch`:

```ts example.ts
import { fetch } from 'expo/fetch';
import { File, Paths } from 'expo-file-system';

const url = 'https://pdfobject.com/pdf/sample.pdf';
const response = await fetch(url);
const src = new File(Paths.cache, 'file.pdf');
await src.write(await response.bytes());
```

</Collapsible>

<Collapsible summary="Previewing files">

Use `File.preview()` to open local files in the native viewer. Android opens an installed
app that supports the file's MIME type. iOS uses Quick Look.

`File.preview()` and `File.canPreview()` accept a `File` or an ordered `File[]`.
For one file, you can also call `file.preview()` and `file.canPreview()` directly.

```ts example.ts
import { File, Paths } from 'expo-file-system';

const file = await File.downloadFileAsync(
  'https://pdfobject.com/pdf/sample.pdf',
  new File(Paths.cache, 'sample.pdf')
);

if (await File.canPreview(file)) {
  await File.preview(file, { title: 'Sample PDF' });
}
```

**Multiple files are supported on iOS only.** This example opens the notes first
and lets the user navigate to the PDF:

```ts example.ts
const notes = new File(Paths.cache, 'notes.txt');
await notes.write('Notes about the PDF');
const files = [file, notes];

if (await File.canPreview(files)) {
  await File.preview(files, { initialIndex: 1 });
}
```

`initialIndex` is zero-based and defaults to `0`. An array with one file works on
both platforms. On Android, passing multiple files makes `File.canPreview()`
resolve to `false` and `File.preview()` reject.

`File.preview()` rejects if you pass `title` or `mimeType` with multiple files.
`File.canPreview()` rejects if you pass `mimeType` with multiple files.
For a single file, `mimeType` defaults to the file's `type`. Pass it explicitly
if the extension does not identify the type, particularly on Android.

`File.canPreview()` resolves to `false` when the platform cannot preview, or when
a checked file is missing or has an unsupported type. It rejects if it encounters
an invalid or unreadable file. `File.preview()` rejects if any file cannot be
previewed or `initialIndex` is invalid. Both methods reject empty arrays.

Keep files available until the viewer closes. `File.preview()` resolves when the
preview is presented or handed off to another app.

If a share sheet is useful in your app, you can compose this with [`expo-sharing`](./sharing/) when previewing fails:

```ts example.ts
import { File, Paths } from 'expo-file-system';
import * as Sharing from 'expo-sharing';

// This can be a file created, picked, or downloaded earlier.
const file = new File(Paths.cache, 'report.pdf');

try {
  await file.preview({ title: 'Report' });
} catch {
  if (await Sharing.isAvailableAsync()) {
    await Sharing.shareAsync(file.uri, {
      dialogTitle: 'Share report',
      mimeType: file.type || 'application/pdf',
    });
  }
}
```

</Collapsible>

<Collapsible summary={<>Uploading files using <CODE>expo/fetch</CODE></>}>

You can upload files as blobs directly with `fetch` built into the Expo package:

```ts example.ts
import { fetch } from 'expo/fetch';
import { File, Paths } from 'expo-file-system';

const file = new File(Paths.cache, 'file.txt');
await file.write('Hello, world!');

const response = await fetch('https://example.com', {
  method: 'POST',
  body: file,
});
```

Or using the `FormData` constructor:

```ts example.ts
import { fetch } from 'expo/fetch';
import { File, Paths } from 'expo-file-system';

const file = new File(Paths.cache, 'file.txt');
await file.write('Hello, world!');
const formData = new FormData();
formData.append('data', file);
const response = await fetch('https://example.com', {
  method: 'POST',
  body: formData,
});
```

</Collapsible>

<Collapsible summary="Moving and copying files">

```ts example.ts
import { Directory, File, Paths } from 'expo-file-system';
try {
  const file = new File(Paths.document, 'example.txt');
  file.create();
  console.log(file.uri); // '${documentDirectory}/example.txt'
  const copiedFile = new File(Paths.cache, 'example-copy.txt');
  file.copy(copiedFile);
  console.log(copiedFile.uri); // '${cacheDirectory}/example-copy.txt'
  file.move(Paths.cache);
  console.log(file.uri); // '${cacheDirectory}/example.txt'
  file.move(new Directory(Paths.cache, 'newFolder'));
  console.log(file.uri); // '${cacheDirectory}/newFolder/example.txt'
} catch (error) {
  console.error(error);
}
```

</Collapsible>

<Collapsible summary="Random-access reads with FileHandle">

Use [`FileHandle`](#filehandle) for efficient, random-access reads of large files without loading the entire file into memory. Obtain a handle by calling `file.open()`, read or write at any position using the `offset` property, and always close the handle when finished.

```ts example.ts
import { File, Paths, FileMode } from 'expo-file-system';

const file = new File(Paths.document, 'recording.wav');
const handle = file.open(FileMode.ReadOnly);

// Read the WAV header (first 44 bytes)
const header = handle.readBytesSync(44);
const sampleRate = new DataView(header.buffer).getUint32(24, true);
console.log(`Sample rate: ${sampleRate} Hz`);

// Seek to a specific offset and read a chunk
handle.offset = 1024;
const chunk = await handle.readBytes(4096);
console.log(`Read ${chunk.length} bytes from offset 1024`);

// Read an entire file in 64 KB chunks
handle.offset = 0;
const CHUNK_SIZE = 64 * 1024;
while (handle.offset! < handle.size!) {
  const data = await handle.readBytes(CHUNK_SIZE);
  // Process data...
}

handle.close();
```

</Collapsible>

<Collapsible summary="Listing directory contents recursively">

```ts example.ts
import { Directory, Paths } from 'expo-file-system';

function printDirectory(directory: Directory, indent: number = 0) {
  console.log(`${' '.repeat(indent)} + ${directory.name}`);
  const contents = directory.list();
  for (const item of contents) {
    if (item instanceof Directory) {
      printDirectory(item, indent + 2);
    } else {
      console.log(`${' '.repeat(indent + 2)} - ${item.name} (${item.size} bytes)`);
    }
  }
}

try {
  printDirectory(new Directory(Paths.cache));
} catch (error) {
  console.error(error);
}
```

</Collapsible>

## Web support

On web, files and directories in `Paths.cache` and `Paths.document` are stored in the browser's [Origin Private File System](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system) (OPFS), under `expo-file-system/cache` and `expo-file-system/document`. They stay there across page reloads. Other files, such as picked files and `https:` URLs, are not stored: the module reads them from memory or with `fetch()`, as described below.

The browser only offers asynchronous access to OPFS, which changes how some members work on web:

- Call `await Paths.ready()` once at startup. It reads the names, sizes, and modification times of the stored files into memory, so that `exists`, `size`, `lastModified`, `list()`, `info()`, and `Paths.info()` can answer synchronously. Until it resolves, they throw an `ERR_NOT_INITIALIZED` error. On Android, iOS, and tvOS, `Paths.ready()` resolves at once.
- Use `createAsync()` and `deleteAsync()` of `File` and `Directory`, and `createFileAsync()` and `createDirectoryAsync()` of `Directory`. The sync `create()`, `delete()`, `createFile()`, `createDirectory()`, `writeSync()`, `textSync()`, `bytesSync()`, `copySync()`, `moveSync()`, and `rename()` throw an `UnavailabilityError` on web, because a sync call cannot wait for the browser. The exception is `File.delete()` on a file that is not stored in OPFS: it still releases the data of the file and revokes its `blob:` URL. The `*Async` methods work on every platform: on Android, iOS, and tvOS, they call the sync methods.
- `write()`, `copy()`, `move()`, and `File.downloadFileAsync()` write to OPFS when the destination is in `Paths.cache` or `Paths.document`. A write rejects with `ERR_FILE_LOCKED` while another write to the same file is open, and with `ERR_QUOTA_EXCEEDED` when the storage quota of the site is used up. Use [`navigator.storage.estimate()`](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/estimate) to see how much space is left.
- `info()` has no `creationTime`, because OPFS does not store it, and `info({ md5: true })` throws.
- A stored `File` does not hold its data in memory, so `slice()` and `toWebFile()` throw, and `FormData` or `fetch()` would send 0 bytes for it. Read the data first: `new globalThis.File([await file.bytes()], file.name, { type: file.type })`.
- `Paths.cache` is as persistent as `Paths.document`: the module never removes files from it. The browser can still clear all storage of the site, for example when the device runs low on space. A page can ask the browser to keep the storage with `navigator.storage.persist()`.

OPFS needs a [secure context](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts) (HTTPS or `localhost`) and a browser that supports [`FileSystemFileHandle.createWritable()`](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable). Without them, `Paths.cache` and `Paths.document` exist but hold nothing, and every write to them rejects with `ERR_OPFS_UNAVAILABLE`.

```ts
import { Directory, File, Paths } from 'expo-file-system';

await Paths.ready();

const notes = new Directory(Paths.document, 'notes');
await notes.createAsync({ idempotent: true });

const file = new File(notes, 'today.txt');
await file.write('Buy milk');
console.log(file.exists, file.size); // true 8
console.log(await file.text()); // Buy milk

await file.deleteAsync();
```

Files that are not stored in OPFS work like this:

- A `File` from `File.pickFileAsync()`, `File.downloadFileAsync()` into a directory outside `Paths.cache` and `Paths.document`, or `File.fromWebFile()` holds its data in memory. It is also a browser [`File`](https://developer.mozilla.org/en-US/docs/Web/API/File), so you can pass it directly to `fetch()` or `FormData`. Its `uri` is a `blob:` URL, and `new File(file.uri)` returns a file with the same data. The data stays in memory until you call `delete()`, which also revokes the URL. To store it, call `await file.move(new Directory(Paths.document))`.
- A `File` created from any other URI, such as a `data:` or `https:` URL, only has the URI. `text()`, `bytes()`, `arrayBuffer()`, `json()`, and `stream()` read it with `fetch()`. `size` and `slice()` throw, `lastModified` is `null`, and `exists` is `true` only for `data:` URIs.
- `File.pickFileAsync()` opens the browser file dialog, so it must be called from a user gesture, such as a click handler. In Chrome 37 to 112 and Safari 15.4 to 16.3, which do not fire the `cancel` event on file inputs, the promise may never settle when the user closes the dialog.
- `Paths.bundle` is the placeholder directory `file:///bundle/`. It exists, but nothing can be stored in it.

The following members are not available on web and throw or reject with an `UnavailabilityError`:

- `File`: `writableStream()`, `open()`, `base64()`, `base64Sync()`, `digest()`, `md5`, `modificationTime`, `creationTime`, `contentUri`, `upload()`, `createUploadTask()`, `File.createDownloadTask()`, `watch()`, `canPreview()`, `preview()`, and the sync methods listed above.
- `Directory`: `copy()`, `copySync()`, `move()`, `moveSync()`, `rename()`, `watch()`, `Directory.pickDirectoryAsync()`, and the sync methods listed above.
- `Paths`: `totalDiskSpace` and `availableDiskSpace`.
