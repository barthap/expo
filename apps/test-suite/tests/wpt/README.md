# Web Platform Tests

The `WPT FileAPI` suite (route `wptfileapi`) runs the upstream
[Web Platform Tests](https://github.com/web-platform-tests/wpt) for `Blob` and `File` on iOS,
Android and web.

- `harness.ts`: a small subset of WPT's `testharness.js` on top of the test-suite's jasmine.
  Each WPT test is one jasmine spec.
- `vendor/`: the upstream files, generated by `scripts/vendor-wpt.mjs`. See
  [`vendor/README.md`](vendor/README.md) for the pinned commit, the skipped files and the license.
- `expectations/<platform>.json`: the known failures of each platform, as
  `{ "<file>": { "<test name>": "fail" } }`.

## Running

Open `/run?tests=wptfileapi` in the test-suite app (for example
`bareexpo://test-suite/run?tests=wptfileapi`, or `http://localhost:19006/run?tests=wptfileapi`
on web). The suite logs one line per file and a total:

```
[WPT] FileAPI/blob/Blob-slice.any.js: 145/150 (5 expected failures)
[WPT] total: 327/346 (19 expected failures)
```

The suite does not run in CI yet; that wiring is deferred.

## Expectations

- A test that is not in the expectations must pass.
- A listed test that fails is marked pending with an `expected failure: <message>` reason. It
  counts neither as passed nor as failed in the test-suite totals.
- A listed test that passes fails with `unexpected pass: remove it from expectations`.
- A listed test or file that does not exist fails the run too.

When a fix makes a listed test pass, remove it from the expectations in the same change.

## Updating the vendored files

Change `WPT_COMMIT` or `FILES` in `scripts/vendor-wpt.mjs`, run `node scripts/vendor-wpt.mjs`
from `apps/test-suite`, run the suite on every platform, and update the expectations and the
table below. Do not edit the vendored files.

Web runs the browser's own `Blob` and `File`; its results match a run of the same files on
wpt.live in the same browser. Two `File-constructor` tests need `document`, so iOS and Android
register 346 tests instead of 348.

Causes of the known failures:

- `MessageChannel` does not exist in Hermes, so the detached-buffer tests and the
  `FrozenArray<MessagePort>` test cannot run (iOS, Android).
- `Float16Array` does not exist in Hermes (iOS, Android).
- `Blob.prototype.textStream()` is not implemented (iOS, Android).
- `slice()` with fractional `start`/`end` does not round like WebIDL `[Clamp]` (round half to
  even): iOS rounds half up and Android truncates.
- `Blob.text()` does not strip a UTF-8 byte order mark on Android.
- Chrome sniffs a UTF-16 byte order mark in `Blob.text()` (web).
